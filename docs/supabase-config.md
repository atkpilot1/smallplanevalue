# Supabase config (git-driven)

Auth and project settings live in git. Do not edit them in the dashboard — the next `config push` will overwrite the dashboard.

Schema is separate: `supabase/migrations/` via `db:push:*`. Config is Auth / API / SMTP via `db:config:*`.

## Why overlays

`supabase config push` reads a single `config.toml`. Local, staging, and production cannot share one Site URL or redirect list. We keep one shared file and a small overlay per environment.

`scripts/supabase-config.mjs` deep-merges `config.shared.toml` + `config.<env>.toml`. Objects merge. **Arrays replace** (redirects are not concatenated).

| File | Role |
|---|---|
| `supabase/config.shared.toml` | OTP length, confirmations, email template, everything that should match across envs |
| `supabase/config.local.toml` | localhost + Playwright `:3100` |
| `supabase/config.staging.toml` | Vercel staging URL, Resend, email rate limit |
| `supabase/config.prod.toml` | `https://www.smallplanevalue.com` + apex redirects. Other Auth keys are still the captured hosted defaults until we choose to change them |
| `supabase/config.toml` | **Generated** for Docker. Do not edit. Regenerated by `db:config:sync` / `db:start` / `db:reset` |

## Commands

`npx supabase login` as an account on the target project first.

| Command | What it does |
|---|---|
| `npm run db:config:sync` | Write local `config.toml` (Docker only) |
| `npm run db:config:dump -- staging` | Print the merge. Does not write remote |
| `npm run db:config:dump -- prod` | Same for production |
| `npm run db:config:push:staging` | Merge + `supabase config push` to `wyggunstezdstrmblkhx` |
| `npm run db:config:push:prod` | Same for `ogfaqdmhqwlysavooroo` |
| `npm run db:push:staging` / `db:push:prod` | SQL migrations only. Does not change Auth |

There is no `config pull`. To see what a push would send, dump first.

`config push` applies as soon as the CLI runs. A printed diff is not a dry-run. Do not push production unless someone explicitly asked.

SMTP passwords stay out of git. Staging overlay uses `pass = "env(RESEND_SMTP_PASSWORD)"`. Export that before `db:config:push:staging`.

After a push, `config.toml` is restored to the local merge so Docker keeps working.
